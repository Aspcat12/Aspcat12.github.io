## 3. ปัญหาและแรงจูงใจ (§1)

**ข้ออ้างตั้งต้น 4 ข้อของเขา:**
1. Dance เป็นศิลปะที่ *"relies on tacit knowledge that resists easy formalization"* และมีลักษณะ **uniqueness** (นักออกแบบท่าคนละคนแทบไม่ผลิตลำดับเดียวกัน) → การ map ความคิดสร้างสรรค์เชิงอัตวิสัยลงกรอบคำนวณจึงเป็นโจทย์ยากโดยธรรมชาติ
2. อ้าง taxonomy ของ **Joshi et al. [62]** ที่แบ่ง "Dance Automation" เป็น 6 ด้าน: representation / capture / semantics / **generation** / dance-processing / systems → แล้วชี้ว่า **generation คือ "pivotal innovation"**
3. ตาม Zhu et al. [201] แบ่ง dance generation เป็น 3 แบบตาม condition: **text-driven / visual-driven / music-driven** → music-driven เป็น *"key research area"* เพราะ artistic synergy + technical feasibility + commercial potential
4. เหตุผลเชิงคุณค่า 5 ข้อ: ลดต้นทุนการออกแบบท่า · เป็นสนามทดลองของ human motion generation · ดัน multimodal AI · อธิบายกลไกชีวกลศาสตร์และหลักสุนทรียะ · ให้ insight เชิง neuroscience เรื่องความเชื่อมโยงดนตรี–การเคลื่อนไหว [11]

**ขอบเขตที่เขาประกาศ (§1 ย่อหน้าสุดท้าย):** *"any choreographic framework where music serves as a primary input modality"* — กว้างกว่า "music-only" เพราะจงใจรวมงาน multimodal ที่มีดนตรีเป็นแกน

## 4. นิยามปัญหาเชิงคณิตศาสตร์ (§2.3) — ส่วนที่ยืมมาเขียน methodology ได้

### 4.1 ตัวแปร
- **Condition** `C` = เซต multimodal ที่มี **music feature sequence M = {m₁,…,m_T}** เป็นแกนบังคับ (Mel-spectrogram, VQ-VAE token, หรือ deep audio embedding) + ตัวเลือก: `T` (text: style / emotion / narrative), `S` (seed motion: ต่อเนื่อง / inpainting / long-sequence), `F` (formation constraint สำหรับ group), `D_L` (leader motion สำหรับ duet follower)
- **Output** `D` แล้วแต่งาน: solo = `p(D | M, T, S)` · duet joint = `p(D_A, D_B | M,…)` · duet reactive = `p(D_F | M, D_L,…)` · group = `p(D₁,…,D_N | M, F,…)`

### 4.2 สมการ (คัดมาตรง)

**Eq. (1) — MLE เชิงเงื่อนไข**
```
θ* = arg max_θ  E_{(C,D) ~ p_data} [ log p_θ(D | C) ]
```

**Eq. (2) — latent variable สำหรับความหลากหลาย**
```
p(D | C) = ∫ p(D | C, z) p(z | C) dz
```
โดย `z` จับ *"variations in timing micro-deviations, stylistic nuances, and individualized expression"*

**Eq. (3) — composite loss**
```
L_total(θ) = Σ_i λ_i(t) · L_i(θ)
```
โดย **น้ำหนัก λ ถูกระบุว่า "often dynamically adjusted rather than fixed"** · องค์ประกอบทั่วไป: `L_rec` (spatial / pose fidelity), `L_beat` (temporal sync), `L_phys` (foot-sliding / joint violation / unnatural dynamics), `L_inter` (multi-dancer: relative pose consistency, collision avoidance, formation)
เทคนิคแก้ gradient conflict ที่เขาลิสต์: uncertainty-based dynamic reweighting, gradient surgery / conflict-aware balancing, Pareto-front approximation, curriculum learning schedules, training-progress-conditioned adaptive weighting

> 📌 **ใช้ได้กับเรา:** Eq. (1) คือสิ่งที่ `train_lstm.py` ทำเป๊ะ ๆ (maximize log-likelihood ของ token ถัดไป) แต่ **ไม่มี condition** → เขียน methodology ได้ว่า "เรา degenerate Eq. (1) ให้ C = ∅" · **Eq. (2) คือกรอบที่อธิบายว่าทำไม decoding strategy ถึงสำคัญ** (ถ้าเราสุ่ม z แบบเดียว ความหลากหลายหายไป) → เชื่อมกับ E8 (top-p sweep) ได้ตรง ๆ

### 4.3 Human motion representation (§2.2) — ตารางที่ใช้ป้องกันตัวได้

| แบบ | ข้อดีที่เขาระบุ | ข้อเสียที่เขาระบุ |
|---|---|---|
| **2D keypoints** (x,y) | ถูก, ได้จากวิดีโอโมโนคูลาร์จำนวนมาก | *"lack depth information"* → อธิบาย 3D displacement / occlusion ไม่ได้ → เกิด **visual "flattening" และ proportion distortion** |
| **3D keypoints** (x,y,z) | บรรยาย spatial trajectory ได้ครบ | *"only defines joint positions mathematically without explicitly constraining limb rotations"* → เกิด **non-physical bone-length stretching** · ขับตัวละคร 3D เกรดอุตสาหกรรมไม่ได้ |
| **3D rotations** (rotation matrix / Euler / quaternion) | **bone-length invariance** → biomechanical fidelity · จับ postural dynamics ละเอียดกว่า | *"non-linear nature of rotation spaces often makes model convergence more challenging"* |
| **Parametric mesh (SMPL / SMPL+H / SMPL-X)** | 6,890 vertices + shape params · รองรับนิ้วและใบหน้า · **เปิดทางใส่ physical constraint (foot-sliding prevention, self-collision avoidance)** | (ไม่ระบุข้อเสีย — เขาเขียนฝั่งเดียว) |

> 🚨 **ข้อความนี้คือคำอธิบายตรง ๆ ของปัญหาที่เราเจอเอง**: เราใช้ **3D keypoints จาก MediaPipe** → ตำราบอกไว้แล้วว่าจะเจอ **bone-length stretching** เพราะไม่มีข้อจำกัดการหมุน → **นี่คือเหตุผลเชิงวรรณกรรมที่ใช้ยืนยัน metric "limb-length SD" ใน E7 ได้ทันที** และเป็นเหตุผลเชิงทฤษฎีของหัวข้อ MediaPipe→SMPL-X ที่เสริมกับตัวเลขเชิงประจักษ์จาก A1-14 (`Assessment_of_monocular...summary.md`: MPJPE 146 มม., ē_z 108 vs ē_x 50 / ē_y 58)
> ⚠️ **แต่ระวัง:** §2.2 ทั้งหัวข้อเขียนเชิงคุณภาพล้วน **ไม่มีตัวเลขสนับสนุนแม้แต่ตัวเดียว** → อ้างได้แค่ในฐานะ "ความเข้าใจร่วมของวงการ" ไม่ใช่หลักฐานเชิงประจักษ์

## 6. §3.2 — คลัง metric พร้อมสูตร ⭐ (ส่วนที่มีค่าที่สุด)

### 6.1 General performance metrics (§3.2.1) — ใช้กับ solo / duet / group ทั้งหมด

**Eq. (4) — FID** [52]
```
FID = ‖μ_r − μ_g‖² + Tr( Σ_r + Σ_g − 2(Σ_r Σ_g)^{1/2} )
```
สมมติ `p_g = N(μ_g, Σ_g)` และ `p_r = N(μ_r, Σ_r)` · แยกเป็น **FID_k (kinematic features [122])** และ **FID_g (geometric features [115])** · ต่ำ = ดี
> 🚨 **[115] ที่เขาอ้างเป็นที่มาของ geometric feature = Müller, Kurth & Clausen, "Chroma-based statistical audio features", WASPAA 2005 → เป็นฟีเจอร์ *เสียง*** (ดู §13 bug #1)
> 📎 **[122] = Onuma, Faloutsos & Hodgins, "FMDistance", Eurographics Short Papers 2008** — อันนี้ถูกต้อง เป็นฟีเจอร์ kinematic ของ mocap จริง

**Eq. (5) — Generation Diversity (Div)** [87]
```
Div = 1 / ( S_samp (S_samp − 1) ) · Σ_{i=1}^{S_samp} Σ_{j ≠ i}^{S_samp} ‖ φ(D_i) − φ(D_j) ‖₂
```
`S_samp` = sample size, `φ(·)` = feature extractor · แยกเป็น **Div_k / Div_g**
**ประโยคที่สำคัญที่สุดของหัวข้อนี้ (คัดตรง):** *"Although larger distances indicate greater variety, a robust model should match the natural variability of real human performances rather than simply maximizing this metric."*
> 📌 ตรงกับหลักการ "fidelity คู่ diversity เสมอ" ที่เราบันทึกไว้จาก SinMDM — **และเปเปอร์นี้ทำจริงกว่า** เพราะกำหนดไว้ใน Table 3 ด้วยลูกศร `→` (closer-to-GT is better) ไม่ใช่ `↑`

**Eq. (6) — Beat Align Score (BAS)** [87]
```
BAS = (1 / |B_m|) · Σ_{b_m ∈ B_m}  exp( − min_{b_d ∈ B_d} ‖ b_m − b_d ‖² / (2σ²) )
```
`B_m` = music beats, `B_d` = dance beats ซึ่ง *"typically defined as local minima of joint motion velocity"* · **σ ไม่ถูกระบุค่า**
> ⚠️ **ช่องโหว่:** ไม่บอกค่า σ ทั้งที่ค่านี้กำหนดสเกลของ BAS ทั้งหมด → **ตัวเลข BAS ใน Table 3 จึงเทียบข้ามเปเปอร์ต้นทางไม่ได้ถ้าเปเปอร์ต้นทางใช้ σ คนละค่า** (เป็นข้อบกพร่องแบบเดียวกับที่เราบันทึกไว้เรื่อง Harmonic Mean ของ SinMDM)

**Eq. (7) — Physical Foot Contact (PFC)** [149 = EDGE]
```
PFC = (1/T) · Σ_{t=1}^{T}  I(h_t < ε) · exp( − ‖v_t‖² / (2σ²) )
```
`I` = indicator ของการสัมผัสพื้น, `ε` = height threshold, `h_t` / `v_t` = ความสูง / ความเร็วของเท้าที่เฟรม `t`
> ⚠️ **สูตรนี้กับทิศทางของลูกศรขัดกัน**: ต้นฉบับระบุเองว่า *"I is an indicator function for **contact**"* → ตามที่เขียน **ค่าสูง = เท้าแตะพื้นและนิ่ง = พฤติกรรมที่พึงประสงค์** แต่ Table 3 ทำเครื่องหมาย **PFC↓ (ต่ำดีกว่า)** · ถ้าจะวัด foot-sliding ให้สอดคล้องกับ ↓ สูตรต้องเป็น `1 − exp(·)` · **หลักฐานว่าลูกศร ↓ คือสิ่งที่เขาตั้งใจ**: บน AIST++ GT ได้ 1.33 ส่วนโมเดลที่เขาชูว่าดีที่สุด (EDMG) ได้ **0.96** และ MeloDance 1.26 → **ห้าม implement PFC จากสมการในเปเปอร์นี้ ต้องไปอ่าน EDGE (Tseng et al., CVPR 2023) ต้นทาง** (ดู §13 bug #3)
> ⚠️ **และอย่าอ้างว่า GT เป็นค่าต่ำสุด** — บน FineDance GT ได้ 0.16 แต่ **Lodge ได้ 0.04 ซึ่งต่ำกว่า**

**User Study:** ระบุแค่ว่าเป็น *"single-blind or double-blind"* โดย *"professional dancers and non-professional viewers"* ให้คะแนนด้าน **realism / artistry / synchronization** — **ไม่มีโปรโตคอล ไม่มีจำนวนคน ไม่มีสเกล ไม่มีความยาวคลิป** → **ด้อยกว่า A1-22 MotionCritic (`2407.02272v2.summary.md`) ที่ให้โปรโตคอลครบ (60 เฟรม @ 24 fps ≈ 2.5 วิ) มาก** → **สำหรับ user study ของเรา ให้ใช้ A1-22 เป็นต้นแบบ ไม่ใช่เปเปอร์นี้**

### 6.2 Task-specific metrics (§3.2.2) — multi-dancer

**(1) Spatial Constraints & Collision Handling**

**Eq. (8) — Contact Frequency (CF)** [90]
```
CF = (1/T) · Σ_{t=1}^{T}  I( min_{v_A ∈ V_A, v_B ∈ V_B} ‖ p_{v_A}(t) − p_{v_B}(t) ‖₂  <  τ )
```
สัดส่วนเฟรมที่ระยะต่ำสุดระหว่าง mesh สองคนต่ำกว่า threshold `τ` → **วัดความเข้มของการปฏิสัมพันธ์** (Table 3: CF↑)

**Eq. (9) — Penetration Rate (PR)** [90]
```
PR = (1 / (T · N_v)) · Σ_{t=1}^{T} Σ_{v ∈ V_A}  I( is_inside( p_v(t), Vol_{B,t} ) )
```
`N_v` = จำนวน vertex ต่อ mesh, `Vol_{B,t}` = ปริมาตรที่ mesh ของ B ล้อมไว้ที่เฟรม t (Table 3: PR↓)

**Eq. (10) — Trajectory Intersection Frequency (TIF)** [74]
```
TIF = (1/T) · Σ_{t=1}^{T}  I( ∃ i ≠ j ∈ {1…N} :  intersect( M(p_i(t)), M(p_j(t)) ) )
```
`M(·)` = SMPL skinning function → สัดส่วนเฟรมที่ mesh ของคู่ใดก็ได้ทับกัน · **ต่ำ = physically plausible กว่า**

**(2) Interaction Coherence & Coupling**

**Eq. (11) — cross-distance feature สำหรับ FID_cd / Div_cd** [99, 138]
```
F(t) = { ‖ p_i^L(t) − p_j^F(t) ‖₂ }_{i,j ∈ {1,…,10}}   ∈ R^100
```
ระยะคู่ระหว่าง **10 key joints ของ leader × 10 ของ follower** → เวกเตอร์ 100 มิติต่อเฟรม · `FID_cd` วัดความสอดคล้องเชิงตรรกะ/เวลาระหว่าง response กับ leader · `Div_cd` วัดความหลากหลายของการโต้ตอบ

**Eq. (12) — Beat Echo Degree (BED)** [90] — เฉพาะ duet
```
BED = exp( − (1/|B_L|) · Σ_{b_L ∈ B_L}  min_{b_F ∈ B_F} | b_L − b_F | )
```
**อ้างอิง "จังหวะของ leader" แทน "จังหวะของเสียง"** → วัด coupling แบบ Leader-Follower

**(3) Group Synchrony & Realism**

**Eq. (13) — Group kinetic feature → GMR** [74]
```
f_j = log( 1 + (1/(N·T)) · Σ_{n=1}^{N} Σ_{t=1}^{T}  m_j · ‖ v_{n,j}(t) ‖² )
```
`v_{n,j}` = ความเร็วของ joint `j` ของนักเต้นคนที่ `n` ที่เฟรม `t`, `m_j` = มวลที่กำหนดให้ joint นั้น → **GMR = เอาสูตร FID (Eq. 4) มาใช้กับเซตฟีเจอร์ kinetic นี้**

**Eq. (14) — Group Motion Correlation (GMC)** [74]
```
GMC = (1/P) · Σ_{(i,j) ∈ Pairs}  Pearson( DTW( φ(D_i), φ(D_j) ) )
```
`P` = จำนวนคู่ = `N(N−1)/2` → จัดลำดับด้วย DTW แล้วหา cross-correlation เฉลี่ย

> 📌 **สิ่งที่เอามาใช้กับ solo ของเราได้ทันที:** **Eq. (13)** — `log(1 + mean(m_j ‖v‖²))` คือ **นิยาม "energy per joint" ที่มีเปเปอร์ Q1 รองรับ** → **ใช้หนุน energy curve ของ Phase 2 ได้ตรง ๆ** (ตอนนี้เราคิด energy จาก landmark velocity ตาม B1-13 Camurri ซึ่ง checklist ข้อ 28 บันทึกไว้ว่าต้องเขียนระบุว่าแทนที่กัน — **Eq. (13) เป็น citation ที่ใกล้สูตรเราและใหม่กว่ามาก**) · ต่างกันตรง `m_j` (มวลต่อ joint) ที่เราไม่มี → ถ้าตั้ง `m_j = 1` ทุก joint จะได้ `log(1 + mean ‖v‖²)` พอดี **ต้องเขียนระบุว่าเราทำแบบนั้น**
> ⚠️ **ข้อควรระวัง:** Eq. (13) ถูกนิยามในบริบท *group* (มี N นักเต้น) การยกมาใช้กับ solo คือ **การ degenerate ให้ N = 1** — ต้องเขียนระบุ ไม่ใช่อ้างว่าเป็นสูตรเดียวกัน

**ข้อสรุปของเขา (คัดตรง) — "three pivotal technological transitions":**
> (1) *"from recurrent architectures (e.g., LSTMs) to global attention mechanisms (e.g., Transformers), which addressed the **'motion freezing' phenomenon** by capturing long-term temporal dependencies"*
> (2) *"from continuous state estimation to discrete latent quantization (e.g., VQ-VAE), which effectively **curtailed error accumulation in autoregressive synthesis**"*
> (3) *"from unstable GAN-based distributions to generative diffusion models (e.g., EDGE, Lodge), which significantly enhance motion fidelity, editability, and cross-modal robustness"*

> 🚨 **ข้อ (1) และ (2) กระทบข้ออ้างของเราโดยตรง — ทั้งบวกและลบ:**
> - **บวก:** ข้อ (2) เป็น **คำรับรองระดับ Q1 ว่า "discretisation ช่วยลด error accumulation ใน AR"** → นี่คือเหตุผลเชิงวรรณกรรมของการเลือก token pipeline ของเรา **ที่เราไม่เคยมี citation มาก่อน** → ใช้คู่กับ L3-30 DC-Motion (`2606.14721v2.summary.md`: "discrete แบกโครงสร้าง / continuous แบกรายละเอียด") ได้ดีมาก
> - **ลบ:** ข้อ (1) บอกว่า **LSTM → Transformer เป็นการเปลี่ยนที่จำเป็นเพื่อแก้ "motion freezing"** → **เป็นแรงกดดันโดยตรงต่อการทดลอง LSTM vs Transformer (ชั้นที่ 1) ของเรา** — ถ้าเราจะรายงานว่า LSTM ชนะหรือเสมอ ต้องอธิบายให้ได้ว่าทำไมผลเราต่างจากที่วงการสรุป (คำตอบที่น่าจะถูก: **corpus เราเล็กเกินกว่าที่ Transformer จะได้เปรียบ** — เชื่อมกับ A1-18 `2407.13623v3` "data เป็นคอขวด")
> - ⚠️ **แต่ทั้ง 3 ข้อนี้ไม่มีตัวเลขหรือ ablation รองรับในเปเปอร์นี้เลย** เป็นข้อสรุปเชิงบรรยายล้วน → **อ้างได้ในฐานะ "ความเห็นของ survey" ไม่ใช่ "ผลการทดลอง"**

### 7.3 §4.3 แกนเป้าหมาย: solo → duet → group

- **Duet (§4.3.1)** — เน้น *reactive generation* (สร้าง follower ตาม leader) · ไล่จาก Mousas et al. [114] (HMM, 2018) → Maluleke et al. [112] (**VQ-VAE + AR transformer**, 2024) → Wu et al. ## 11. §6 ปัญหาคอขวด และ §7 ทิศทางอนาคต

### 11.1 §6.1 "Key points" — 3 ชั้นของปัญหา
1. **Foundation: representation** — ดนตรีมีโครงสร้างเป็นชั้น (low: beat/rhythm · mid: melody/harmony · high: emotion/semantics) · ท่าเต้นมีทั้ง local dynamics (joint angle, velocity) และ global pattern (pose sequence, body trajectory) · **representation ต้องจับทั้ง discrete element (beat, dance step) และ continuous dynamics (acoustic spectra, joint rotation curve)** · ถ้าไม่ครบ → beat drift / emotional misalignment [113]
2. **Core technology: mapping** — ต้องการ **temporal alignment (millisecond-level)** + **semantic consistency** + **structural correspondence (musical phrase ↔ dance segment)** · ความท้าทาย: data alignment แย่, annotation เบาบาง, style bias → *"overfitting to local rhythms, overlooking long-term structure"*
3. **Objective: high-quality output** — 3 มิติ: **visual** (ลื่น, ท่าธรรมชาติ, foot sliding น้อย) · **physical** (ข้อจำกัดข้อต่อ, ground support, momentum conservation) · **perceptual** (style สม่ำเสมอ, emotion เหมาะสม, diversity/creativity) · **และยอมรับว่าเป้าหมายจริงคือหา trade-off ไม่ใช่ทำให้สุดทั้ง 3 ด้าน**

### 11.2 §6.2 Challenge 3 ข้อ

| Challenge | สาระ | ทิศทางที่เสนอ |
|---|---|---|
| **Controllable** | control signal ต่างกันที่ semantic granularity / numerical distribution / temporal scale → **ข้อจำกัดแน่นไป = mode collapse, หลวมไป = semantic drift** · ขาด *"structured decoupling mechanism between discrete semantic spaces and continuous motion spaces"* · โมเดลมักสร้างท่า exaggerated ที่ **ละเมิดขีดจำกัดชีวกลศาสตร์** (center-of-mass shift เกิน, joint torque เกินสรีระ, ground impact force ไม่สมส่วน) | (1) physics-aware conditional diffusion/flow ที่ใส่ biomechanical feasibility เป็น constraint / posterior regularizer (2) multi-level control interface (keyframe + style + soft physical constraint) |
| **Long-term** | ต้องรักษาทั้ง micro-level temporal consistency และ macro-level narrative coherence · ยืดไปหลายร้อย–หลายพันเฟรม → **cumulative error + distribution drift → คุณภาพตก + "flattened emotional arcs"** [148] · ผลลัพธ์เป็น *"fragmented concatenations of locally optimal actions"* ขาดตรรกะการออกแบบท่าแบบมืออาชีพ (โครงสร้าง **"introduction–elucidation–transition–conclusion"**, การพัฒนา core motif, การไต่และคลายความตึงทางอารมณ์) → เรียกว่า **"motion stacking" แทนที่จะเป็น "structural weaving"** | (1) ใช้ multimodal LLM เป็น high-level choreographic reasoner (2) รวม physics-based differentiable simulation เข้ากับ latent diffusion |
| **Group** | role heterogeneity (lead vs supporting ตอบสนอง melody/harmony/timbre ด้วยน้ำหนักต่างกัน → *"same input, distinct interpretation"*) · physical constraint (collision, CoM coordination) + social constraint (emotional sync, formation transition) ที่ **ซับซ้อนแบบ exponential** · ข้อมูลขาดแคลน → มักสร้างแยกแล้วค่อย validate หรือใช้ interaction แบบ stereotyped | มองเป็น **complex multi-agent dynamic system** ตามแนวคิด systems science |

> 📌📌 **"motion stacking" vs "structural weaving" คือคำที่เราต้องการมานาน** — มันคือชื่อที่วงการให้กับปัญหาที่ **Phase 2 (energy-structure analysis) ของเราตั้งใจจะวัดพอดี** · **โครงสร้าง "introduction–elucidation–transition–conclusion"** ก็เป็นอนาล็อกตรงของ narrative arc ที่ template Phase 2 (L2-5 `paperหนัง.pdf`) ใช้
> → **ถ้าเราจะกู้ Phase 2 กลับมาเป็น extension ใน thesis นี่คือ citation ที่ทำให้มันไม่ใช่ความคิดลอย ๆ** — survey ฉบับ Q1 ระบุเองว่านี่คือช่องว่างที่วงการยังแก้ไม่ได้
> → **และมันยังให้เหตุผลกับ E9 (exposure-bias check ที่ rollout 10/50/120)**: *"cumulative errors and distribution drift"* + *"flattened emotional arcs"* คือสิ่งที่ E9 วัดพอดี

### 11.3 §7 ทิศทางอนาคต 3 ข้อ + ethics
1. **high-quality standardized datasets** — ชุดปัจจุบัน *"limited in scale, lack diversity, and suffer from inconsistent annotations"* → ต้องการ multimodal ขนาดใหญ่ (3D pose + music + video) ที่ annotate ด้วย **standardized protocol** ครอบคลุมหลาย genre / style / **cultural background** / interaction scenario
2. **multidimensional evaluation frameworks** — *"Existing evaluation metrics often fail to capture nuanced elements such as emotional expression, energy dynamics, choreographic structure, and aesthetic qualities"* → ต้องรวม objective + subjective + **ประเมินคุณภาพการ model ร่างกาย (morphological integrity, realism) [184,185]** และ **identity consistency [189] ภายใต้กรอบจริยธรรม**
3. **unified multimodal large-scale dance models**
4. **socio-technical boundaries** (ย่อหน้าที่ยาวและเฉพาะเจาะจงที่สุดใน §7): copyright/IP (training พึ่ง mocap + งานออกแบบท่าที่มีอยู่ → derivative infringement, data sovereignty · AI-generated dance เป็นงานอันมีลิขสิทธิ์เองได้ไหมยังไม่มีข้อยุติในกฎหมายระหว่างประเทศ) · ethics (job displacement ของนักแสดง, **cultural appropriation เมื่อเทรนบนสไตล์ของชนกลุ่มน้อยโดยไม่ใส่บริบท**) · misuse (fake video, publicity right, privacy) → เสนอ ethical review framework, transparency ของที่มาข้อมูล, watermarking / provenance-tracking

> 📌 **ข้อ 1 + ข้อ 4 ให้อาวุธกับเราโดยตรง:** *"cultural background"* ถูกระบุเป็นมิติที่ dataset ยังขาด และ *"cultural appropriation ... styles indigenous to specific ethnic or minority communities without proper contextualization"* ถูกยกเป็นความเสี่ยงเชิงจริยธรรม → **งานรำไทยที่ทำโดยคนไทย บนข้อมูลที่เก็บเอง = ตอบโจทย์ที่ survey ตั้งไว้พอดี** ใช้เขียนใน Introduction / Significance ได้
> 📌 **ข้อ 2 = คำรับรองว่า metric ปัจจุบันไม่พอ** — *"fail to capture ... energy dynamics, choreographic structure"* → **นี่คือชื่อของ Phase 2 เราเป๊ะ ๆ** (energy curve + structure)

## 17. บทสรุปในประโยคเดียว

> **เปเปอร์นี้คือแผนที่ระดับ Q1 ของสาย music-driven dance generation ที่ให้ของจริง 3 อย่างกับเรา — 11 สมการครอบคลุม 14 metric (Eq. 4–14), ทะเบียน 28 dataset ที่ยืนยันว่านาฏศิลป์ไทยและ MediaPipe ยังเป็นช่องว่าง, และคำรับรองว่า "discretisation ลด error accumulation ใน AR" — แต่ส่วนเชิงปริมาณของมัน (Table 3) เป็นการรวบรวมตัวเลขจากเปเปอร์อื่นโดยไม่ประกาศที่มา ไม่มี error bar และมีกรณี "โมเดลชนะ Ground Truth" กระจายอยู่ทั่วตาราง — หนักที่สุดคือ BAS ที่โมเดล *ทุกตัว* ชนะมนุษย์จริงในบล็อก duet ทั้งสอง (10/10) — ซึ่งกลับกลายเป็นหลักฐานชิ้นดีที่สุดที่เราได้จากมัน ว่า BAS / FID / BED เป็น conformity metric ไม่ใช่ quality metric.**

### 18.7 สถานะสุดท้าย
