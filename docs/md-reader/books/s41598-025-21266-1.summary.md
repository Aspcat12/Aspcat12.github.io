2. **🔴 คำว่า `codebook` ปรากฏ 0 ครั้งในทั้งเปเปอร์** (ตรวจ **2 ชั้น**: regex บน text layer ทั้ง 21 หน้า **+ อ่านกล่อง pseudocode หน้า 9 ด้วยตาจากภาพ** เพราะกล่องนั้นไม่อยู่ใน text layer — ยืนยันซ้ำโดย fact-audit อิสระ) · `VQ-VAE` ปรากฏ 2 ครั้ง · **ไม่มีค่า k, ไม่มีขนาด codebook, ไม่มี reconstruction error, ไม่มี codebook usage, ไม่มี commitment loss, ไม่มี encoder/decoder ของ VQ-VAE** → **คำนวณ bitrate `log₂V·C·R` ตาม DASB (checklist ข้อ 3) ไม่ได้** และ **เทียบกับ V=216 ของเราไม่ได้เลยแม้แต่เชิงคุณภาพ**

3. **🔴 Eq. (15) [k-means] กับ Eq. (16) [VQ-VAE] เป็นสมการเดียวกันเขียนสองครั้ง.**
   Eq. (15): `Q(Zi) = Ci , j = arg(min_k ‖Zi − Ck‖)` · Eq. (16): `Zq = arg(min_j ‖Z − Cj‖)`
   → ทั้งคู่คือ nearest-centroid argmin เหมือนกันเป๊ะ ต่างแค่ชื่อตัวแปร. **สิ่งที่ทำให้ VQ-VAE เป็น VQ-VAE (codebook ที่เรียนรู้ได้ + straight-through estimator + commitment loss) ไม่ปรากฏเลย** → เปเปอร์นี้ **ไม่ได้อธิบาย VQ-VAE จริง** เท่าที่ข้อความบอกได้

4. **🔴 pose quantization เป็นขั้นตอนปลายทางที่ไม่เชื่อมกับอะไรเลย.** การทำนายท่าคือ Eq. (12) `X̂_{t+1} = f_GCN-MHW(X_t, A)` ซึ่งเป็น **regression บนพิกัดต่อเนื่อง** ไม่ใช่การทำนาย token. quantization (Eq. 14–16) ถูกวางไว้ *หลัง* GCN แล้ว **ไม่มีที่ไหนอธิบายว่า token ถูกใช้ต่ออย่างไร** → **"pose quantization" ในชื่อเรื่องเป็นของประดับ ไม่ใช่กลไก**
   🔴 **หลักฐานชี้ขาด: pseudocode ของเปเปอร์เอง (หน้า 9, 17 ขั้นตอน) ไม่มีขั้นตอน quantization เลยแม้แต่ขั้นเดียว** — ไล่จาก Mel-spectrogram → audio token → keypoint → early fusion → SE-ViT → embeddings Z → skeleton graph → GCN-MHW → `15: Apply DE-based optimization on decoded motion embeddings` → L_sync → output · **ไม่มี k-means ไม่มี VQ-VAE ไม่มี codebook** ทั้งที่ย่อหน้าเหนือกล่องนั้นเพิ่งเขียนว่า *"K-means clustering and vector-quantized variational autoencoders are used to quantize the final features"* · ⚠️ **นี่ทำให้เปเปอร์นี้ไม่ใช่ "เพื่อนบ้านที่ใกล้ที่สุด" อย่างที่ checklist เดาไว้** — สถาปัตยกรรมของเรา (token → LSTM → token) ไม่มีอยู่ในเปเปอร์นี้

## 5. วิธีการ — สมการที่สำคัญ (§"The proposed architecture")

### 5.1 SE-ViT
- **Eq. (1)** positional encoding แบบ sinusoid (fixed, non-trainable) · ⚠️ เขียนผิดรูป: `ξn[i] = sin(2πf, i), cos(2πf, i)(ξf, 2πf)` — argument อ่านไม่ได้
- **Eq. (2)** scaled dot-product + concat 3 heads · **Eq. (3)** residual + LayerNorm · **Eq. (4)** FFN 2 ชั้น + GeLU
- **Eq. (5)** SE block: global average pooling → FC → ReLU → FC → Sigmoid → scale channel
- **Eq. (6)** CLS token → FC → softmax · **Eq. (7)** `ψ_SE = SE-ViT(X_pose)`
- ⚠️ **ไม่ระบุ: จำนวน transformer block, embedding dimension, SE reduction ratio, จำนวน patch token** ทั้งที่เขียนว่า *"detailed to ensure reproducibility"*

### 5.2 GCN-MHW
- **Eq. (8)** adjacency `A_ij ∈ {0,1}` · **Eq. (9)** joint feature `X_i^t = [x,y,z,v]` (**d = 4**) · **Eq. (10)** GCN มาตรฐาน `H^{l+1} = ψ(D̄^{-1/2} Ā D̄^{-1/2} H^{(l)} W^{(l)})`
- **Eq. (11)** แทน activation ด้วย **Mexican-Hat (Ricker) wavelet** `ψ(t) = 1/(√(2π)σ³)·(1 − t²/σ²)·exp(−t²/2σ²)`
  **เหตุผลที่เปเปอร์ให้:** band-pass → เน้นความถี่กลาง กด noise ทั้งความถี่ต่ำและสูง → จับ oscillatory/rhythmic pattern ได้ดีกว่า ReLU/sigmoid
  ⚠️ **ไม่มีค่า σ ที่ใช้จริง ไม่มี ablation σ** และ **wavelet นี้ไม่ monotonic** (มีค่าลบสองข้าง) → ผลต่อ gradient ไม่ถูกวิเคราะห์เลย
- **temporal convolution** `H^{l+1}_t = Σ_{τ=−T}^{T} W_τ H^{(l)}_{t+τ}` ⚠️ **ไม่ระบุค่า T**
- **Eq. (12)** `X̂_{t+1} = f_GCN-MHW(X_t, A)` ← **นี่คือ motion prediction ทั้งหมดของเปเปอร์: single-step regression** ไม่มี long-horizon rollout ไม่มี autoregressive loop

### 5.3 Beat-aligned loss
**Eq. (13)** `L = γ₁L_pose + γ₂L_motion + γ₃L_sync`
- `L_pose` = MSE ระหว่างท่าที่ทำนายกับ ground truth
- `L_motion` = motion continuity (ผลต่างระหว่าง 2 เฟรม)
- `L_sync` = การจัดท่าให้ตรง tempo ⚠️ **ไม่มีสูตร** — นิยามด้วยประโยคเดียว
- ⚠️ **ไม่เคยรายงานค่า γ₁, γ₂, γ₃ ที่ DE หาได้** ทั้งที่มันคือ contribution ข้อ 3 ของเปเปอร์

### 5.4 Pose quantization (§ต่อจาก Eq. 13)
- **Eq. (14)** `Z = GCN-MHW(X, A)` · **Eq. (15)** k-means: `Q(Zi) = Ci, j = arg(min_k ‖Zi − Ck‖)` · **Eq. (16)** VQ-VAE: `Zq = arg(min_j ‖Z − Cj‖)`
- 🔴 **สองสมการเดียวกัน** (ดู §"อ่านตรงนี้ก่อน" ข้อ 3) · **ไม่มี k, ไม่มีขนาด codebook, ไม่มี loss ของ quantizer, ไม่มีการใช้ token ต่อ** · ref [62] ที่อ้างเป็นที่มาของ VQ-VAE เป็นงาน **voice conversion**

### 5.4b 🔴 กล่อง pseudocode หน้า 9 — หลักฐานที่แรงที่สุดในเปเปอร์ (ไม่อยู่ใน text layer ต้องอ่านจากภาพ)
อัลกอริทึมของเปเปอร์เองมี **17 ขั้นตอน**: (1) Mel-spectrogram (2) แบ่งเป็น audio token (3–6) `for t = 1 to T:` **"4: Extract keypoints from pose frame p_t using OpenPose"**, **"5: Form token τ_t = [a_t ⊕ p_t] via early fusion"** (7–9) SE-ViT encoder + positional encoding + MHA + FFN + SE (10) `Z = {z_1..z_T}` (11–14) สร้าง skeleton graph + อัปเดต node ด้วย GCN-MHW (15) **"Apply DE-based optimization on decoded motion embeddings"** (16) minimize `L_sync` (17) output `P̂`

**สามสิ่งที่กล่องนี้เปิดโปง:**
1. 🔴 **ไม่มีขั้นตอน quantization เลย** — ไม่มี k-means ไม่มี VQ-VAE ไม่มี codebook ทั้งที่ย่อหน้าเหนือกล่องเพิ่งเขียนว่า *"K-means clustering and vector-quantized variational autoencoders are used to quantize the final features"* → **contribution ที่อยู่ในชื่อเรื่องไม่อยู่ในอัลกอริทึมของตัวเอง**
2. 🔴 **"using OpenPose"** — คำว่า OpenPose **ปรากฏที่เดียวในทั้งเปเปอร์ ไม่เคยถูกอ้างอิง** และ **ขัดกับ abstract โดยตรง** ที่เขียนว่า *"high-dimensional pose characteristics are extracted from dance video frames using modified vision transformer"* → **ขัดแย้งเรื่องสถาปัตยกรรมแกนกลาง ไม่ใช่แค่ตัวเลข**
3. 🔴 **"via early fusion" ถูก hard-code ในขั้นตอนที่ 5** → **Ablation-1 ที่เทียบ NoFu / LaFu / EaFu เป็นไปไม่ได้ภายใต้อัลกอริทึมที่ประกาศไว้เอง** · และขั้นที่ 15 พูดถึง *"decoded"* embeddings ทั้งที่ **ไม่มี decoder อธิบายไว้ที่ใดเลย**

### 5.5 DE variants
- **Eq. (17)** DE มาตรฐาน `V_i = X_r1 + F·(X_r2 − X_r3)`, ปกติ F = 0.5
- **Eq. (18) Variant-I** `V_i = X_r1 + rand()·(X_r2 − X_r3)` — รูปแบบ DE ปกติที่สุ่ม F
- **Eq. (19) Variant-II** `V_i = X_r1 + 1/(1 + exp(X_r2 − X_r3))`
  🔴 **นี่ไม่ใช่ "F = log-sigmoid()"** — (ก) `1/(1+e^x)` คือ **sigmoid** ไม่ใช่ **log-sigmoid** (`log σ(x)`) (ข) **พจน์ผลต่าง `(X_r2 − X_r3)` หายไปจากการคูณ** ถูกกลืนเข้าไปในฟังก์ชัน → step ที่ได้เป็นค่าในช่วง (0,1) ที่ **หดลงเมื่อผลต่างโตขึ้น** ซึ่งตรงข้ามกับหลักการ DE ทั้งหมด (ค) **ไม่มีสัญญาณทิศทางจาก population เหลืออยู่เลย**
  → **ถ้าจะ reimplement ต้องรู้ว่าเราไม่รู้ว่าเขาทำอะไรจริง** และ *"F = log-sigmoid"* ที่ปรากฏทุกตารางไม่มีนิยามที่สอดคล้องกับ Eq. (19)
- **Table 3 (DE config):** population **120**, iterations **1500**, CR **0.85**, target fval **10⁻¹¹**

## 7. สมมติฐานและข้อจำกัด

### 7.1 🔴 ข้อจำกัดที่เปเปอร์ไม่ยอมรับ (จาก pass 3)
1. **ไม่มีหัวข้อ Limitations เลย** — คำว่า `limitation` ปรากฏ **1 ครั้ง** ในทั้งเปเปอร์ และหมายถึงข้อจำกัดของ *งานคนอื่น*
2. **split protocol ตรวจสอบไม่ได้ และขัดกันเอง** — เปเปอร์บอกว่า *"randomly partitioned"* 80:20 แต่ได้ test set ที่ **สมดุลเป๊ะ 400 ต่อคลาส** ซึ่งการสุ่มให้ไม่ได้ (§6.2) · **ถ้า** หน่วยคือเฟรม (4000 ตัวอย่างจาก 1408 คลิป — เป็นการอนุมาน เปเปอร์ไม่ระบุ) การสุ่มระดับเฟรมจะทำให้เฟรมจากคลิปเดียวกันอยู่คนละฝั่ง = leakage → **ในกรณีนั้นตัวเลข 97% ไม่ใช่ generalisation** · เปเปอร์ไม่ให้ข้อมูลพอจะตัดความเป็นไปได้นี้ออก
3. **ไม่มี human evaluation เลย** ทั้งที่เคลมเรื่อง *"authentic"*, *"realistic"*, *"emotive"* ซ้ำ ๆ → **ปัญหาเดียวกับ L3-5 (`2607.13978v1.summary.md`) เป๊ะ** ใช้อ้างคู่กันได้เป็น pattern ของวงการ
4. **ไม่มี code, ไม่มี seed, ไม่มี split file** — Data availability มีแค่ลิงก์ AIST++
5. **motion prediction เป็น single-step regression** (Eq. 12) → **ไม่มีหลักฐานเรื่อง long-horizon** เลย ขณะที่คำว่า "choreography" สื่อถึงลำดับยาว
6. **ค่า hyperparameter ของทุก contribution หายไปหมด**: k (k-means), ขนาด codebook, σ (wavelet), T (temporal window), γ₁γ₂γ₃ (ผลลัพธ์ของ DE ซึ่งเป็น contribution ข้อ 3)

### 7.2 สมมติฐานที่ไม่ได้ประกาศ
- สมมติว่า **beat alignment สูง = การเต้นดี** (ไม่พิสูจน์) → ⚠️ **ขัดกับหลักฐานที่เรามีแล้ว**: `2111.12159v1.summary.md` (A1-16) และ `2603.27314v1.summary.md` (L3-21) ต่างบันทึกว่า **BAS/chi-square เป็น conformity metric ไม่ใช่ quality metric** และ generator ทำคะแนนชนะ ground truth ได้
- สมมติว่า **FID บน kinetic/geometric feature = คุณภาพ** โดยไม่แตะข้อจำกัดของ FID บน corpus เล็ก
- สมมติว่า **skeleton graph จาก AIST++ = input ที่สะอาด** — ไม่มีการพูดถึง noise ของ pose estimation เลย (ต่างจาก A1-14 ที่ให้งบความคลาดเคลื่อนจริง)

## 9. ความสัมพันธ์กับงานข้างเคียง และกับคลังของเรา

### 9.1 ตำแหน่งในคลัง — checklist "ต้องให้คุณช่วย · L3-29"

|---|---|
