## ตารางสกัดของ อ.Proadpran

| ช่อง | สาระ |
|---|---|
| **Motivation** | คุณภาพของระบบสร้าง motion ขึ้นกับ 2 อย่าง [56]: **faithfulness** (ตรงกับสัญญาณเงื่อนไข) และ **naturalness** (ลื่นไหลเหมือนจริง) · ฝั่ง **continuous** ได้ naturalness แต่แพ้ faithfulness เพราะ mapping ข้าม modality คลุมเครือในปริภูมิมิติสูง + ข้อมูล mocap น้อย · ฝั่ง **discrete** ได้ faithfulness (เปลี่ยนเป็นปัญหา classification) แต่เจอ 2 โรค: **under-reconstruction** (รายละเอียดหายตอน quantize) และ **frame-wise noise** (decode token ตรง ๆ แล้วได้ artifact สั่น ๆ) → เรียกความขัดแย้งนี้ว่า "discord" |
| **Research Question** | จะได้ทั้ง faithfulness ของ discrete และ naturalness ของ continuous พร้อมกันได้ไหม **โดยไม่ต้องแตะ stage 1 (quantizer) และ stage 2 (token predictor) ที่เทรนไว้แล้ว** |
| **Proposed Method** | เปลี่ยน **เฉพาะ decoder** — แทนที่จะ map token → motion แบบ feed-forward ให้ใช้ token เป็น **เงื่อนไขระดับเฟรม** ของ conditional **rectified flow** ที่สร้าง motion ขึ้นจาก Gaussian noise ในปริภูมิ raw motion แบบวนซ้ำ |
| **Evaluation** | 2 ชั้นแยกกัน: **(ก) reconstruction** (decode token จริงจาก encoder) วัดด้วย FID / MPJPE / sJPE · **(ข) generation** (decode token ที่โมเดล stage 2 ทำนายออกมา) วัดด้วย FID / R-Precision / MM-Dist / MModality (text-to-motion), FGD (gesture), Dist_k·Dist_g·FID_k·FID_g·BAS (dance) + user study 2 ชุด |
| **Contribution ต่อวงกว้าง** | เสนอว่า **"decoder ของ VQ-VAE ควรเป็น generative model ไม่ใช่ regressor"** เป็นของที่เสียบเข้ากับ pipeline discrete ที่มีอยู่แล้วได้ทันที + เสนอ metric ที่จับ artifact ระดับเฟรมซึ่ง FID/MPJPE มองไม่เห็น |

## PASS 2 — เนื้อหาโดยละเอียด

### 1. ปัญหาและแรงจูงใจ (§1)

สองโรคของ motion VQ-VAE ที่เปเปอร์ตั้งชื่อไว้ชัด:

1. **Under-reconstruction** — รายละเอียดการเคลื่อนไหวละเอียด ๆ ที่จำเป็นต่อท่าเร็ว/ซับซ้อน หายไปตอน discretize
2. **Frame-wise noise** — การ decode token ตรง ๆ ทำให้ความ "เป็นขั้น" ของ token รั่วลงไปเป็น artifact สั่นในเฟรม

และตั้งข้อสังเกตเรื่อง metric: MPJPE **ไม่ correlate กับการรับรู้ของมนุษย์** [9, 18] ส่วน FID เป็น metric ระดับ model (ดึง feature จาก network ที่ pretrain มา) จึง **จับ naturalness ระดับ sample ไม่ได้** [57] และ **ไม่ไวต่อ noise ระดับเฟรม** (Figure 4)

### 2. Preliminaries (§3.1)

**Rectified flow** — มอง generation เป็นปัญหา transport แก้ด้วย ODE

- ODE: `dx_t = v(x_t, t) dt` … Eq. (1)
- forward process: `x_t = t·x_1 + (1−t)·x_0` … Eq. (2) โดย `v = x_1 − x_0`
- เทรนด้วย least-squares: `min_v ∫₀¹ E‖(x_1 − x_0) − v̂(x_t, t)‖² dt` … Eq. (3)

จุดขายเทียบ diffusion ทั่วไป: trajectory เกือบเป็นเส้นตรง → ใช้ **จำนวน step น้อยกว่ามาก**

**Motion tokenization** — สรุปสูตร 2 stage มาตรฐาน: stage 1 เทรน VQ-VAE (encoder E: `X = [x_1..x_T]`, `x_t ∈ R^{d_motion}` → token `Z = [z_1..z_{T/q}]` จาก codebook `Z = {z_k ∈ R^{d_code}}_{k=1}^{N}`, downsample factor `q`, decoder D สร้าง `X_recon` กลับ, loss = reconstruction + commitment) · stage 2 เทรนโมเดลทำนาย index ถัดไปบน `S = [s_1..s_{T/q}]` โดยมีเงื่อนไขเป็นสัญญาณต่าง ๆ

### 3. DisCoRD (§3.2) — วิธีการ

**(ก) Condition Projection** — ปัญหา: token `z_t` ตัวเดียวครอบ q เฟรม แต่เราต้องการ feature **คนละตัวต่อเฟรม**
- ทางที่เขา *ไม่* เอา: upsample + linear ธรรมดา → ได้ feature เหมือนกัน q ตัว; upconvolution → ทิ้งความสัมพันธ์ token↔เฟรม
- ทางที่เขาทำ: repeat `z_t` q ครั้ง → `z_t^repeat ∈ R^{q×d_code}` → **stack** เป็น `z_t^stacked ∈ R^{1×(q·d_code)}` → project เป็น `R^{1×(q·d_feat)}` → **unstack** กลับเป็น `z_t^final ∈ R^{q×d_feat}` → ได้ `C = [c_1..c_T]`, `c_i ∈ R^{d_feat}`
- เขาอ้างว่าวิธีนี้ยังช่วยเรื่อง **generalisation ไปยัง token sequence ที่ไม่เคยเห็นใน stage 2** ด้วย (มีหลักฐานใน ablation Table 6)

**(ข) Rectified Flow Decoder** — เทรน conditional rectified flow จาก `X_0 ~ N(0, I)` ไป `X_1 ~ P_X` โดยมี `C` เป็นเงื่อนไขระดับเฟรม:
`min_v ∫₀¹ E[‖(X_1 − X_0) − v(X_t, t, C)‖²] dt` โดย `X_t = t·X_1 + (1−t)·X_0` … **Eq. (4)**
- `C` ถูก **concat ตามแกน channel** (ทำตาม [16, 67] ฝั่งภาพ) → แต่ละเฟรมถูก condition แยกกันเป็นอิสระ
- ตอน inference: ดึง `Ĉ` จาก token ที่ stage 2 ทำนาย → แก้ ODE ด้วย **Euler method**

**(ค) 2 ทางเลือกการเทรนที่สวนทางสามัญสำนึก (และมีหลักฐานรองรับ)**
1. เทรนบน **sliding window** (64 เฟรม) ไม่ใช่ทั้ง sequence (196 เฟรมแบบมาตรฐาน HumanML3D) — เพราะการเทรนเต็ม sequence ทำให้ **stage 1 ดีขึ้นแต่ stage 2 แย่ลง**
2. **ไม่ใส่ attention** ใน U-Net backbone — ใส่แล้วแย่ลง

**Implementation (Table A, บน HumanML3D + quantizer ของ MoMask):** U-Net 66.9M params, width (512, 1024), 2 resnet/block, SiLU, dropout 0 · input ch **512** (codebook ของ MoMask 512 มิติ), output ch **263** (มิติ feature ของ HumanML3D), condition ch **256** · window size **64**, batch **768**, **200 epochs / 481,896 steps**, AdamW(0.9, 0.999), lr **5e-4** cosine, warmup 20 epochs, grad clip 1.0, EMA 0.999, MSE flow loss · **เทรน 35 ชั่วโมงบน NVIDIA RTX 4090 Ti ใบเดียว**

### 4. sJPE — metric ใหม่ (§4.1 + Supp. C)

Jerk = อนุพันธ์อันดับสามของตำแหน่งเทียบเวลา · เปเปอร์อ้างว่า jerk เป็นตัววัดความไม่ราบรื่นที่ใช้ได้จริง [3, 4, 7, 23]

**สูตรหลัก — Eq. (5):**
```
sJPE = (1/n) · Σ_{t=1..n}  |J_pred,t − J_true,t| / (|J_true,t| + |J_pred,t|)
```
(เป็น symmetric MAPE [34] บนค่า jerk)

**แยกเป็น 2 องค์ประกอบ:**
```
Noise  sJPE = (1/n) Σ max(0, J_pred,t − J_true,t) / (|J_true,t| + |J_pred,t|)   … Eq. (6)   → jerk เกิน = frame-wise noise
Static sJPE = (1/n) Σ max(0, J_true,t − J_pred,t) / (|J_true,t| + |J_pred,t|)   … Eq. (7)   → jerk ขาด = under-reconstruction
sJPE = Noise sJPE + Static sJPE                                                 … Eq. (8)
```

**วิธีดึง fine-grained trajectory (Supp. C.1)** — 3 ขั้น: (1) เลือก joint ที่เคลื่อนไหวเยอะ (มักเป็นข้อมือ/มือ) แล้วติดตามตำแหน่งตามเวลา (2) กรอง Gaussian ให้เรียบ (3) **เอา trajectory เดิมลบตัวที่เรียบแล้ว** → เหลือส่วนประกอบละเอียด
⚠️ **ระวังอย่าเข้าใจผิด:** หัวข้อ C.1 ชื่อ *"Visualization of Fine-Grained Motion"* และปิดท้ายว่า *"The visualizations in Figure 5 ... are generated using this process"* → ขั้นตอนนี้เป็น **วิธีทำรูป ไม่ใช่ pre-processing ของ sJPE** · Eq. 5–8 นิยามบน `J_pred,t` / `J_true,t` ตรง ๆ โดยไม่พูดถึงการเลือก joint หรือการกรองใด ๆ เลย

**หลักฐานว่า sJPE ไวกว่า FID (Figure 4):** เติม Gaussian noise ลง ground-truth motion โดยไล่ค่า std จาก 0 → 0.0010 · **sJPE พุ่งจาก ~0 ไป ~0.45** (ขับโดย Noise sJPE ล้วน ๆ; Static sJPE แทบไม่ขยับ) ขณะที่ **FID ขึ้นแค่ ~0 → ~0.0020** — คนละสเกล

**หลักฐานว่า sJPE ตรงกับมนุษย์ (Supp. C.4):** user study ให้จัดอันดับ naturalness ของ MLD / MoMask / Ours (ที่ 1 = 1 คะแนน, ที่ 3 = 3 คะแนน) โดยใช้ GT เป็นขอบบน · **ตัดตัวอย่าง 10% ล่างสุดที่ human score มี SD ต่ำสุดออก** (ถือว่ามนุษย์แยกไม่ออก) → **Pearson corr เฉลี่ยของ MPJPE กับคะแนนมนุษย์ = 0.181, ของ sJPE = 0.483** (สูงกว่า ~2.7 เท่า)

## PASS 3 — ท้าทายสมมติฐาน

### จุดแข็ง (เอาไปหนุนงานเราได้)

1. **ตั้งชื่อและวัด "jitter" ได้** — `sJPE` แยก *noise เกิน* ออกจาก *dynamic ขาด* ด้วยสูตรบรรทัดเดียวบน jerk **ไม่ต้องมี pretrained encoder, ไม่ต้องมี corpus, ไม่ต้องมี torch** → เป็น metric ที่ถูกที่สุดในบรรดาที่เราเจอมาทั้งคลัง *(แต่ใช้เทียบภายในการทดลองของเราเท่านั้น — เทียบข้ามเปเปอร์ไม่ได้ ดูจุดอ่อนข้อ 7)*
2. **หลักฐานเชิงปริมาณว่า FID มองไม่เห็น frame-wise noise** (Figure 4: sJPE 0→0.45 แต่ FID 0→0.0020 บนช่วง noise std เดียวกัน) — ใช้อ้างได้ตรง ๆ ว่า **การรายงาน FID ตัวเดียวไม่พอสำหรับงานที่ output เป็น token**
3. **หลักฐานว่า "stage 1 ดีขึ้น ไม่ได้แปลว่า stage 2 ดีขึ้น"** (Table 6 แถว Full Motion Sequence: recon FID ดีที่สุด 0.008 แต่ gen FID แย่ลง) — เป็นคำเตือนเชิงโครงสร้างที่ใช้ได้กับ pipeline 2 stage ทุกอัน รวมของเรา
4. **Table 5 เป็น ablation ที่สะอาด** — สัมพันธ์ระหว่าง "ความจุข้อมูลของ token" กับ "ค่าใช้จ่ายด้าน faithfulness ของ decoder แบบ generative" ไล่เป็นระบบจาก −2.8% ถึง +0.6%
5. **ต้นทุนเชิงประจักษ์ครบ** — บอกทั้งชั่วโมงเทรน (35 ชม./1 GPU), จำนวนพารามิเตอร์ (66.9M), และเวลา decode ต่อ batch ที่หลายจำนวน step → reproducible กว่าเปเปอร์ส่วนใหญ่ในกองนี้

### จุดอ่อน (เอาไปพูดในเปเปอร์เราได้ / เอามาเตือนตัวเอง)

1. **ความขัดแย้งภายในเรื่อง FID** — §4.1 ใช้ทั้งหน้าพิสูจน์ว่า *FID จับ naturalness ระดับ sample ไม่ได้และไม่ไวต่อ frame-wise noise* แล้ว §4.2 ใช้ **การที่ FID ดีขึ้น** เป็นหลักฐานหลักว่า *naturalness ดีขึ้น* ("particularly in terms of FID, achieving state-of-the-art performance in naturalness") — **ใช้ metric ที่ตัวเองเพิ่ง discredit มาเป็นหลักฐานของ claim หลัก**
2. **sJPE หายไปจากตาราง generation ของ text-to-motion** — Table 2 และครึ่ง generation ของ Table 6 **ไม่มีคอลัมน์ sJPE เลย** ทั้งที่ sJPE คือ contribution ข้อ 2 และ naturalness ตอน generate คือ claim หลัก · sJPE ปรากฏเฉพาะตอน reconstruction (Table 1, 6) และในงาน gesture/dance (Table 3, 4) → **หลุมที่ใหญ่ที่สุดของการทดลอง**
3. **"consistently outperforms" ไม่จริง** — FID_g บน AIST++ แย่ลง 4.4 เท่า (20.09 → 88.74) และถูกเก็บไว้ใน supplementary
4. **abstract เคลม SOTA บน KIT-ML ทั้งที่ตารางตัวเองบอกว่าเป็นที่ 2** (0.169 vs ReMoDiffuse 0.155)
5. **MPJPE แย่ลงเกือบทุกแถว** แล้วใช้ "MPJPE ไม่ตรงกับมนุษย์" ปิดประเด็น — ข้อแก้ต่างถูกต้องในหลักการ แต่ **ไม่มีการรายงานว่าความคลาดเคลื่อนเชิงตำแหน่งที่เพิ่มขึ้น 13–27% นั้นไปโผล่ที่ไหน** (+19.2% / +21.1% / +12.9% / +26.5% ตามลำดับแถวใน Table 1) — ลอยเหนือพื้น? เท้าไถล? แขนยืด? · **ไม่มี foot-skating %, ไม่มี limb-length SD, ไม่มี penetration** เลยสักตัว ทั้งที่ decoder แบบ generative มีความเสี่ยงเรื่อง physical plausibility โดยตรง
6. **user study อ่อนทางสถิติ** — ไม่มี CI/นัยสำคัญบน win rate, ไม่มี inter-rater agreement, ไม่รายงาน N ของ study ที่ 2, **ทั้งสอง study ตัดมือ/นิ้ว/ใบหน้าออกจากการประเมิน** (ขณะที่ fine-grained analysis ของเขาเน้นที่มือ), และการ **ตัด 10% ของตัวอย่างที่ SD ของคะแนนมนุษย์ต่ำสุดออกก่อนคิด correlation** เป็น preprocessing ที่ **ดันค่า correlation ขึ้นได้โดยโครงสร้าง** (ตัด sample ที่ signal ต่ำออก) — ไม่มี sensitivity analysis ว่าถ้าไม่ตัดจะได้เท่าไร
7. **`sJPE` reproduce จากตัวเปเปอร์อย่างเดียวไม่ได้** — Eq. 5–8 บอกแค่ว่าคิดจาก `J_pred,t` กับ `J_true,t` แต่ **ไม่บอกว่า (ก) คิดจาก joint ไหน / กี่ joint (ข) ในระบบพิกัดไหน (root-relative? world?) (ค) หน่วยอะไร (ง) มีการ filter ก่อนหาอนุพันธ์ไหม** · การหาอนุพันธ์อันดับ 3 เชิงตัวเลขจากตำแหน่งนั้น **ไวต่อ noise อย่างยิ่ง** — คำตอบของข้อ (ง) เปลี่ยนค่าที่ได้อย่างมีนัยสำคัญ · และไม่มี ablation/sensitivity ของ sJPE เองเลย
8. **sJPE ยังไม่ normalize ต่อ scale** — เป็น percentage error จึงไม่ขึ้นกับหน่วย แต่ตัวส่วน `|J_true| + |J_pred|` จะเล็กมากในช่วงที่คนแทบไม่ขยับ → **แต่ละเทอมจะเข้าใกล้ 1 ได้ง่ายในช่วง near-static** ซึ่ง **จะทำให้คลิปที่มีช่วงหยุดนิ่งยาว ๆ ได้ sJPE สูงเกินจริง** (สำคัญมากกับเราที่คลิปเต้นมีช่วง hold) — เปเปอร์ไม่พูดถึงเลย
9. **ไม่มี venue / peer review ที่ยืนยันได้จากไฟล์** (ดูกล่องเตือนบนสุด)
10. **bibliography ซ้ำซ้อน 3 คู่** — [51]/[52] = MDM (Tevet et al., ICLR 2023), [6]/[60] = MLD, **[54]/[55] = van den Oord et al. *Neural discrete representation learning* (ลงเป็น "NeurIPS 30, 2017" กับ "2018")** → เปเปอร์อ้าง VQ-VAE เป็นสองรายการคนละเลข
11. **ตัวเลข MoMask baseline ไม่ตรงกันเองระหว่างตาราง** — generation FID ของ MoMask = **0.045** ใน Table 2 และใน Table 5 แถว MoMask-R5 แต่ = **0.051±.002** ใน Table 6 (MM-Dist ก็ต่าง: 2.958 vs 2.957) · เนื่องจาก **headline ของ ablation คือ 0.051 → 0.032** การใช้เลขที่ใหญ่กว่าเป็นฐาน **ทำให้ส่วนต่างดูมากกว่าที่ควร** (ถ้าใช้ 0.045 ส่วนต่างหดจาก ~37% เหลือ ~29%) — เปเปอร์ไม่อธิบายความต่างนี้เลย

### สิ่งที่เขาไม่ได้ทำ แต่เป็นข้ออ้างที่สำคัญของเรา

- **ไม่แตะเรื่อง vocabulary ควรใหญ่แค่ไหน** — รับ quantizer ที่ pretrain มาแล้วทั้งดุ้น ไม่มี sweep V
- **ไม่แตะเรื่อง token มาจากไหน** — codebook ทุกตัวในเปเปอร์นี้ **เรียนรู้ผ่าน VQ/RQ-VAE** ไม่มีตัวไหนมาจาก **clustering บน pose ดิบ** แบบเรา → **white space ของเรายังอยู่ครบ** เปเปอร์นี้เป็นงาน "ทำให้ decoder ดีขึ้น" ไม่ใช่ "ทำให้ vocabulary ดีขึ้น"
- **ไม่มีการทดลองเรื่องความยาว rollout / exposure bias** — สร้างที่ความยาวคงที่ตามชุดข้อมูล

## สิ่งที่ใช้ได้กับโปรเจกต์เราทันที

1. **`sJPE` คือ metric ที่คุ้มที่สุดที่ได้จากเปเปอร์นี้** — คิดจาก jerk (อนุพันธ์ 3 ของตำแหน่ง) เทียบกับ ground truth ไม่ต้องมี encoder ใด ๆ · เราสร้าง reconstruction จาก token ได้อยู่แล้ว → **คำนวณ sJPE ของ pipeline เราได้เลยวันนี้** และ **แยกได้ว่า jitter ของเราเป็น "noise" หรือ "static"** ซึ่งชี้คนละทางแก้: Noise สูง = ปัญหา decoder/การ reconstruct, Static สูง = ปัญหา vocabulary หยาบเกินไป
   ⚠️ แต่ต้อง **กำหนดและรายงานรายละเอียดเองทั้งหมด** — joint ที่ใช้, ระบบพิกัด, หน่วย, และวิธีหาอนุพันธ์อันดับ 3 (เปเปอร์ไม่บอกสักข้อ ดูจุดอ่อนข้อ 7) และ **ระวังช่วง near-static** (จุดอ่อนข้อ 8)
2. **ปิดข้อ 23 ของ checklist ได้ตามเจตนาเดิม** — ตอนนี้เรามี **ชื่อเรียกและตัวเลขอ้างอิง** สำหรับ jitter ของเรา: *frame-wise noise*, เป็นผลพวงที่รู้จักกันแล้วของการ decode discrete token แบบ feed-forward, วัดได้ด้วย Noise sJPE, และ **ไม่ใช่ข้อบกพร่องเฉพาะของเรา** — discrete baseline ทุกตัวในวรรณกรรมมี (sJPE 0.512–0.564 บน HumanML3D) ขณะที่ continuous method อย่าง MLD อยู่ที่ 0.404 → **เขียนลง Limitations ได้ทันทีพร้อม citation**
   ⚠️ **แต่ห้ามเอา sJPE ของเราไปวางข้างตัวเลข 0.512–0.564 ในตารางเดียวกัน** — ต่างชุดข้อมูล ต่าง skeleton และต้นทางไม่ระบุ spec การคำนวณ · ตัวเลขชุดนั้นใช้เป็น **หลักฐานเชิงคุณภาพว่าปัญหานี้เป็นของวงการ** เท่านั้น
3. **หลักฐานสนับสนุนการรายงาน metric หลายตัว** — Figure 4 ทำให้ "เรารายงาน FID ตัวเดียวไม่ได้" เป็นข้อเท็จจริงที่มี reference
4. **คำเตือนเรื่อง 2-stage** (Table 6) — ถ้าเราจะ tune tokenizer โดยดู reconstruction error อย่างเดียว เปเปอร์นี้มีหลักฐานว่าอาจไปผิดทาง **ต้องวัดที่ปลาย generation ด้วยเสมอ**
5. **ขอบเขต novelty ของเรายังปลอดภัย** — DisCoRD ไม่แตะเรื่องที่มาของ vocabulary เลย

### การทดลองใหม่ที่การอ่านรอบนี้เสนอ (ต่อจาก E1–E11)

- **E12. คำนวณ sJPE (+ แยก Noise/Static) บน reconstruction ของ pipeline เรา** — เทียบ (ก) token→pose reconstruct ตรง ๆ กับ (ข) landmark ดิบ · ถ้า **Static sJPE เด่น** = vocabulary หยาบไป (แก้ด้วย V หรือ window rate) · ถ้า **Noise sJPE เด่น** = ปัญหาการ reconstruct/dedup (แก้ด้วย Eq. 8 ของ A1-21 หรือ smoothing)
  ⚠️ **ต้องเขียน spec ของเราเองให้ครบและประกาศไว้** — joint ที่ใช้ (ทั้ง 33 หรือเฉพาะบางกลุ่ม?), root-relative หรือ world, หน่วย, และ finite-difference แบบไหน — เพราะ **ต้นทางไม่ระบุเลย ตัวเลข sJPE ของเราจะเทียบกับตัวเลขในเปเปอร์ตรง ๆ ไม่ได้** ใช้ได้เฉพาะเทียบภายในการทดลองของเราเอง
- **E13. sanity check ของ sJPE บนคลิปที่มีช่วงหยุดนิ่ง** — ตรวจข้อสงสัยในจุดอ่อนข้อ 8 ว่าช่วง near-static ดัน sJPE ขึ้นจริงไหม ก่อนจะรายงานตัวเลขนี้ในวิทยานิพนธ์
